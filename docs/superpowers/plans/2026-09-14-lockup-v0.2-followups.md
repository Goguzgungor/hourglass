# Lockup v0.2 follow-ups (deferred findings)

Items the final review classified as "fix later" — not blocking, but tracked
here so they aren't lost.

## CRITICAL — contracts

- **`withdraw` after `cancel` ignores `refunded`.** `withdrawable = streamed(now) − withdrawn` lets a canceled recipient withdraw up to `deposited` from the contract's pooled balance (other streams' funds). Fix in `contracts/shared/src/math.rs::withdrawable_amount`: cap `streamed` at `deposited − refunded`; add an invariant test that advances time after `cancel` and asserts `withdrawable ≤ deposited − refunded − withdrawn`; redeploy testnet. Belongs in PR #1 (`feat/batch-recurring`) or a follow-up before any mainnet. The read layer (`frontend/src/lib/streaming.ts::withdrawableNow`) already applies the cap, so the API under-reports relative to the contract until this ships.

## Fix later

- **API hardening (indexer/api v2 review):** adversarial `params.ts` / cursor tests (over-long, non-base64url, deeply nested JSON cursors) plus a length cap on the `cursor` parameter before decoding; a builder-level malformed-cursor test in `streamsQuery.test.ts` (today only `cursor.test.ts` covers it); `handleEvent`'s `canceled` / `renounced` branches and the `burned`-without-an-existing-doc branch are untested; `mapStream` has no test for an unknown shape tag hitting the `throw`.
- **Indexer semantics (indexer/api v2 review):** actions materialized on the live path record `participants` using the recipient at fetch time, so a replay after a long outage can attribute a pre-transfer action to the later owner — `backfillParticipants()` reconstructs it correctly, but the live path could use the same `recipientAt` logic.
- **Code polish (indexer/api v2 review):** redundant `as` casts and the now-dead `?? String(err)` fallbacks in a couple of error helpers; make the `503` payload shape consistent across the API routes (each route hand-rolls its empty payload); `/api/stats` fetches full stream docs with no projection or cap for a wallet's aggregate — project only the fields `walletStats` reads and bound the scan; the dashboard's `streamedFraction` duplicates vesting math that belongs in the shared `src/lib/streaming.ts`.
- **Frontend (sub-project 3, before public beta):** `frontend/src/app/stream/[id]/page.tsx` `recurringToTranches` is unbounded — a stream with a huge `count` (e.g. 1e8 × 1 stroop) would OOM the detail page; add a `Recurring` variant to the view `StreamShape` with O(1) math in `LiveCounter` and cap the rendered unlock list (first N + "and X more"). SDK/frontend batch chunk size: default ~20–25 rows (30 linear rows fit on testnet with one recipient; distinct recipients and tranched rows fit fewer); keep `MAX_BATCH_ROWS = 100` as the upper bound.
- **Indexer (sub-project 2):** `frontend/scripts/indexer.ts` shape mapping uses a bare `else` for Recurring — make it an explicit `tag === 'Recurring'` arm with a fallthrough error so a 4th shape cannot be stored as Recurring with NaN fields. Consider a shared discriminated-union helper in `frontend/src/lib` (shape handling now lives in `indexer.ts`, `db.ts`, `page.tsx`). Expose `created_tx` as a query key (batch membership).
- **Tests:** convert bare `#[should_panic]` tests in `contracts/lockup/src/tests/{linear,tranched}.rs` to `contract_error` assertions and add cases for `StartAfterEnd`, unlock-sum `Overflow`, `TooManyTranches`, tranche-sum `Overflow`; add an in-process 100-row batch success test that reads `env.cost_estimate().budget()`; optionally collapse the two event-count helpers in `tests/batch.rs` into one parameterised helper.
- **Scripts:** `scripts/smoke-testnet.sh` — `START = NOW+15` / `FIRST = NOW+20` leave ~10 s of `StartInPast` margin on a slow testnet; recompute `NOW` per create or use +60. `scripts/deploy-testnet.sh` — use `mktemp "$DEPLOYMENT.XXXXXX"` so the rename is atomic on the same filesystem. Friendbot retry loops abort on `curl` failure (pre-existing).
- **SDK:** `sdk/scripts/regen-bindings.sh` runs `npm install` in each generated subpackage and churns their `package-lock.json` on every regen — use `npm ci` or ignore those lockfiles.
- **Code polish:** `contracts/lockup/src/create.rs` `validate_tranched` keeps a redundant `let tranches: &Vec<Tranche> = &p.tranches;` alias.
- **Process:** before committing generated `test_snapshots`, diff the snapshot file names against `fn` names in the test modules to catch orphans.
